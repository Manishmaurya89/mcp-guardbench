# Sample report

Generated by a real run of the demo, including the open-source Cisco MCP Scanner:

```bash
make setup
make cisco-demo          # installs cisco-ai-mcp-scanner==4.8.4 into .venv-scanners/, runs offline
GUARDBENCH_CISCO_MCP_SCANNER=.venv-scanners/bin/mcp-scanner \
  guardbench benchmark run --project demo --cases test_cases/ \
    --adapter no-defense-baseline --adapter reference-static --adapter reference-runtime \
    --adapter cisco-mcp-scanner \
    --output reports/sample --format json --format markdown --format csv
```

**These results were obtained from local reference fixtures shipped with this repository.** They
describe only the four adapters named above, against the 12 test cases in `test_cases/`, under the
default policy, not any real MCP server. The Cisco scanner ran with its YARA analyzer only (its API and
LLM analyzers need keys and were not used). See [`../../docs/limitations.md`](../../docs/limitations.md)
before drawing conclusions from these numbers.

* [`report.md`](report.md): the full Markdown report (configuration, per-case results, metrics,
  findings, reproducibility metadata).
* [`report.json`](report.json): the same report as structured data.
* [`summary.csv`](summary.csv): the metrics table only, for spreadsheets.

Without the Cisco scanner, `make demo && make report` produces the same numbers for the other three
adapters. Every value is reproducible from the recorded `seed`, `policy_sha256`, and `test_corpus_sha256`
in the report's "Reproducibility" section (latency and timestamps differ between runs; verdicts do not).
